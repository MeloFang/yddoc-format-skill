# 中文公文与材料格式规范

一套**开箱即用**的中文公文与对内材料格式规范，含版式参数、文种口径、用词规范、校对规则、排版脚本与 Word 模板。

源自一家真实企业的公文实践，参数已按通用中文公文习惯整理并**全部脱敏**——不含任何企业名、文号代字、地名或敏感内容，可直接使用，也可按你所在单位的规定修改。

---

## 这套规范解决什么问题

写材料时最烦的不是内容，是格式：页边距多少、标题用什么字体、行距几倍、序号怎么排、材料里的表格图片怎么处理、写完还有没有错别字。

这些事每次都要重新交代一遍，或者每次都要自己翻旧文件比对。这套规范把这些固化下来，让 AI 助手（或你自己）一次对齐。

**适用对象**：

- 公文：通知、报告、批复、请示
- 材料：汇报材料、发言稿、总结、方案、普通文章

## 三种用法

### 用法一：作为 WorkBuddy Skill（推荐）

放到技能目录后，新对话里说一句「写份通知」就会自动加载，按规范执行。

```bash
# 复制整个目录到技能目录
cp -r 中文公文与材料格式规范-开源版 ~/.workbuddy/skills/company-doc-format
```

触发方式（任选一句）：

> 「写份关于XX的通知」/「起草一个请示」/「出份汇报材料」/「把这个改成公司格式」/「校对一下这份稿子」/「套模板出个 Word」

### 用法二：作为知识库文档

把 `references/` 下的 md（或根目录的整合版）上传到任意 AI 平台知识库，让其他 AI 助手检索调用。

| 文件 | 内容 |
|---|---|
| `references/format-rules.md` | 页面、字体、行距、层级序数、附件、落款、表格与图片 |
| `references/genre.md` | 文种与结尾语、标题构成、行文方向 |
| `references/wording-rules.md` | 禁用词、称谓口径、引用格式 |
| `references/review-rules.md` | 错别字、病句、遣词造句优化 |

### 用法三：纯参考

直接读 md，照着给自己单位的模板定型。

## 规范速览

| 项目 | 参数 |
|---|---|
| 纸张 | A4 |
| 页边距 | 上 3.7 / 下 3.5 / 左 2.8 / 右 2.6 cm |
| 页眉页脚 | 页眉 1.5 cm / 页脚 2.6 cm，奇偶页不同 |
| 文档网格 | 每行 28 字、每页 22 行 |
| 标题 | 方正小标宋简体，三号，居中 |
| 正文 | 中文仿宋_GB2312，西文 Times New Roman，小四 |
| 行距 | 1.5 倍 |
| 缩进 | 首行缩进 2 字符，两端对齐 |
| 层级序数 | 一、→（一）→ 1. →（1），禁用自动编号 |
| 一级标题 | 黑体（仅限标题性短句） |
| 二级标题 | 楷体_GB2312（仅限标题性短句） |
| 落款 | 正文下空 3 行，日期后缩进 4 字符 |
| 表格 | 表内仿宋_GB2312 五号、表头加粗居中、表内形似标题的文字按正文处理、数字右对齐、整表居中、宽不超 15.6 cm |
| 图片 | 居中、按比例缩放、不跨页，图题在图下方 |

> 完整规则与例外见 `references/format-rules.md`。

**一个容易踩的坑**：带序数不等于就是标题。序数后接短语式标题（「（一）追责触发条件」）才用楷体；序数后展开完整叙述句（「（一）以上标准适用于……」）属**正文**，用仿宋_GB2312。

## 排版脚本

把 Markdown 渲染成符合本规范的 Word 文档：

```bash
# 安装依赖
pip install python-docx

# 渲染
python scripts/render_docx.py draft.md out.docx
```

Markdown 约定：

| 写法 | 含义 |
|---|---|
| `# 标题` | 文档标题（小标宋三号居中） |
| `## 一级标题` | 黑体 |
| `### 二级标题` | 楷体_GB2312 |
| 普通行 | 正文 |
| `{{SIGN}}` | 落款单位 |
| `{{DATE}}` | 日期 |
| `{{ATTACH:文件名}}` | 附件 |

脚本已内置页面设置、字体、1.5 倍行距与落款规则。

### 表内字体统一：`scripts/fix_table_font.py`

给**已存在的 .docx** 批量统一表格内文字字体（默认仿宋_GB2312 五号），表头加粗保留，表内形似标题的文字一并按正文处理：

```bash
python scripts/fix_table_font.py 源文件.docx                    # 输出「源文件名（表格仿宋修正）.docx」
python scripts/fix_table_font.py 源文件.docx -o 输出.docx --zh 仿宋_GB2312 --size 10.5
python scripts/fix_table_font.py 源文件.docx --no-size          # 只改字体，不动原字号
```

脚本会同时修正**段落标记**的字体，并在结束后打印中文字体槽位的分布做自检。

> ⚠️ 用 python-docx 改中文字体有个坑：`run.font.name` 只写西文槽位（ascii/hAnsi），
> 中文字体必须单独写 `w:eastAsia` **且写在最后**。顺序写反会让 Word 找不到中文字体而回退成宋体，
> 表现就是「明明设了仿宋，中文看着还是宋体」。详见 `references/format-rules.md` 9.1.1。

## 字体说明

本规范涉及以下字体，脚本与模板只引用字体**名称**，不含字体文件：

- 方正小标宋简体（标题）
- 仿宋_GB2312 / 楷体_GB2312 / 黑体（正文与层级标题；**表格内文字亦为仿宋_GB2312**）
- Times New Roman（西文）
- 微软雅黑（表题、图题）

部分字体（如方正小标宋简体）为商业字体，需自行购买安装；Windows 与常见中文字体包通常自带仿宋_GB2312、楷体_GB2312、黑体。**若字体缺失，Word 会自动替换，版式会有细微差异**——可改用「方正小标宋简体 → 黑体」「仿宋_GB2312 → 仿宋」等替代方案。

## 改成你自己的规范

1. **改版式参数**：编辑 `references/format-rules.md`（页面、字体、行距、层级、表格图片）
2. **改文种口径**：编辑 `references/genre.md`（文种、结尾语、标题公式）
3. **改用词口径**：编辑 `references/wording-rules.md`（禁用词、称谓、引用格式）
4. **改硬边界与工作流**：编辑 `SKILL.md`
5. **换模板**：替换 `assets/发文模板-通知.docx` 为你单位的真实模板

> 若同时改了规则文档和模板，记得 `scripts/render_docx.py` 里也内置了一份参数，三处要同步——否则会出现「规则写了但生成的文件不对」。

## 关于脱敏

本套规范在整理时已移除全部具象信息：单位名称、文号代字、所属集团、所在地、业务标题、金额标准、联系人等，均以占位符呈现（如 `<本部全称>`、`<代字>〔YYYY〕N号`、`XX分公司`）。

**这也是使用建议**：把你单位的真实名称、代字写进规范前，先想清楚这份文件会不会流出去。规范本身（格式参数）不敏感，敏感的永远是里面填的具体内容。
